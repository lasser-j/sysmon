# Build Guide

## Prerequisites

| Tool | Minimum version |
|---|---|
| CMake | 3.25 |
| GCC or Clang | C++20 required, CI tests GCC 13 and Clang 18 |
| Ninja | any recent (generator used by the CMake presets and all build commands) |
| Git | any recent |

### Test and Benchmark Dependencies

GoogleTest and Google Benchmark are fetched automatically via CMake `FetchContent` at configure time. This requires an internet connection on the first build. Subsequent builds use the cached download under `build/_deps/`.

For offline or corporate environments where outbound network access is restricted, point `FetchContent` at local source checkouts:

```bash
cmake -B build \
  -DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=/path/to/googletest \
  -DFETCHCONTENT_SOURCE_DIR_GOOGLEBENCHMARK=/path/to/benchmark
```

## Build Options

| Option | Default | Description |
|---|---|---|
| `CMAKE_BUILD_TYPE` | none | `Debug` or `Release` |
| `BUILD_TESTING` | `ON` | Build test targets (GoogleTest, sanitizers, see `SANITIZER`) |
| `BUILD_BENCHMARKS` | `ON` | Build benchmark targets (Google Benchmark, skipped when cross-compiling) |
| `SANITIZER` | `address` | Sanitizer for test targets: `address` (ASan + UBSan) or `thread` (TSan) |

## Native Build

### Development build

Builds the libraries with tests, which run with ASan + UBSan. The `dev` and `tsan` presets in `CMakePresets.json` were added for VS Code (see below) and work the same in the terminal. They switch the benchmarks off, because timings from a sanitized Debug build are not representative (see Benchmarks below):

```bash
cmake --preset dev
cmake --build --preset dev --parallel

# All tests
ctest --preset dev

# A single module
ctest --preset dev -R concurrent
```

### ThreadSanitizer build

ASan and TSan cannot be combined, so TSan needs its own build directory:

```bash
cmake --preset tsan
cmake --build --preset tsan --parallel
ctest --preset tsan
```

On WSL2, TSan aborts with `unexpected memory mapping` because of the address space randomization. Run the build and the tests under `setarch -R`, which disables randomization for the started process. The build needs it too, because the test list is generated by running the freshly linked test executable:

```bash
setarch -R cmake --build --preset tsan --parallel
setarch -R ctest --preset tsan
```

### Production build

Without tests and benchmarks:

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_BENCHMARKS=OFF
cmake --build build --parallel
```

### How the sanitizers are applied

Sanitizers are enabled on test targets only. The tests link against a second build of the library sources that carries the sanitizer flags, so the code under test is checked as well and not just the test code. The regular library targets and the benchmarks are never sanitized.

### VS Code

The repository recommends the CMake Tools and C/C++ extensions in `.vscode/extensions.json`. CMake Tools picks up `CMakePresets.json` and offers `dev` and `tsan` as configurations in the status bar. Building, running and debugging single tests works from the Testing panel. The `tsan` preset needs `setarch -R` on WSL2, which is only available in the terminal for now.

## Test Conventions

The tests do not use sleeps for synchronization. They coordinate through latches and futures, and a deadlock caused by a bug in the code under test is reported as a failure by the ctest timeout.

## Benchmarks

Benchmarks should be run from a Release build, since Debug timings are not representative. The `release` preset builds only the benchmarks (no tests) into `build-release/`:

```bash
cmake --preset release
cmake --build --preset release --parallel
./build-release/libs/concurrent/benchmarks/concurrent_benchmarks
```

The benchmarks link the regular `concurrent::concurrent` library and never the sanitized copy. Google Benchmark options select a subset or repeat runs for more stable numbers:

```bash
./build-release/libs/concurrent/benchmarks/concurrent_benchmarks --benchmark_filter=Scaling --benchmark_repetitions=5 --benchmark_report_aggregates_only=true
```

# Build Guide

## Prerequisites

| Tool | Minimum version |
|---|---|
| CMake | 3.25 |
| GCC | 12 (C++20 required) |
| Clang | 15 (C++20 required) |
| Git | any recent |

### Test and Benchmark Dependencies

GoogleTest and Google Benchmark are fetched automatically via CMake `FetchContent` at configure time. This requires an internet connection on the first build. Subsequent builds use the cached download under `build/_deps/`.

For offline or corporate environments where outbound network access is restricted, point `FetchContent` at local source checkouts:

```bash
cmake -B build \
  -DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=/path/to/googletest \
  -DFETCHCONTENT_SOURCE_DIR_GOOGLEBENCHMARK=/path/to/benchmark
```

## Build Options

| Option | Default | Description |
|---|---|---|
| `CMAKE_BUILD_TYPE` | none | `Debug` or `Release` |
| `BUILD_TESTING` | `ON` | Build test targets (GoogleTest, sanitizers, see `SANITIZER`) |
| `BUILD_BENCHMARKS` | `ON` | Build benchmark targets (Google Benchmark, skipped when cross-compiling) |
| `SANITIZER` | `address` | Sanitizer for test targets: `address` (ASan + UBSan) or `thread` (TSan) |

## Native Build

### Development build

Builds the libraries with tests and benchmarks. The tests run with ASan + UBSan:

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel

# All tests
ctest --test-dir build --output-on-failure

# A single module
ctest --test-dir build -R concurrent --output-on-failure
```

### ThreadSanitizer build

ASan and TSan cannot be combined, so TSan needs its own build directory:

```bash
cmake -B build-tsan -DCMAKE_BUILD_TYPE=Debug -DSANITIZER=thread
cmake --build build-tsan --parallel
ctest --test-dir build-tsan --output-on-failure
```

On WSL2, TSan aborts with `unexpected memory mapping` because of the address space randomization. Run the build and the tests under `setarch -R`, which disables randomization for the started process. The build needs it too, because the test list is generated by running the freshly linked test executable:

```bash
setarch -R cmake --build build-tsan --parallel
setarch -R ctest --test-dir build-tsan --output-on-failure
```

### Production build

Without tests and benchmarks:

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_BENCHMARKS=OFF
cmake --build build --parallel
```

### How the sanitizers are applied

Sanitizers are enabled on test targets only. The tests link against a second build of the library sources that carries the sanitizer flags, so the code under test is checked as well and not just the test code. The regular library targets and the benchmarks are never sanitized.

## Test Conventions

The tests do not use sleeps for synchronization. They coordinate through latches and futures, and a deadlock caused by a bug in the code under test is reported as a failure by the ctest timeout.

## Benchmarks

Benchmarks should be run from a Release build, since Debug timings are not representative:

```bash
cmake -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --parallel
./build-release/libs/concurrent/benchmarks/concurrent_benchmarks
```
